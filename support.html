Tell us what happened.

Use the public GitHub issue tracker for bugs, questions, and feature requests. A GitHub account is required to submit an issue.

Open a support request
Support issues are public. Never post passwords, API tokens, Authorization headers, unredacted logs, site-storage snapshots, private Jira URLs, or screenshots/video containing confidential information. Use a synthetic example instead.

Helpful details

  • Extension version and Chrome version.
  • Your operating system.
  • Whether the problem affects screenshots, recording, annotation, settings, or Jira submission.
  • Steps to reproduce, expected behavior, actual behavior, and a sanitized error message.
  • Whether Jira is Server or Data Center. Do not include private hostnames or credentials.

Before reporting

  • Reload the extension at chrome://extensions and reopen its popup after an update.
  • Use an HTTPS Jira base URL, including the correct context path. API redirects are rejected.
  • Try capture on a normal webpage, not a restricted browser page.
  • For recording, click Record and confirm the first-use disclosure unless you previously remembered approval.
  • Stop recordings before attaching them. An attachment failure can occur after the issue was created; check the returned issue link before creating another issue.

Privacy questions

Read the privacy policy. You may open a support request about privacy without posting personal data or captured evidence. If sensitive details are necessary, first request a private contact channel without including those details in the public issue.

Clear Credentials removes the credentials stored by the extension, but does not revoke a Jira token. Clear/reset captured evidence when no longer needed. Uploaded content must be managed through your Jira instance; downloaded files must be deleted separately.
